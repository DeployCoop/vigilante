# 🚀 Getting Started with Vigilante

Welcome to **Vigilante**. This guide walks you through bootstrapping your system, configuring prerequisites, spinning up local Kubernetes clusters (using either **k3d** or native **k3s**), launching both the Web Portal and Terminal interfaces, and joining a CTF cyber range tournament.

---

## 1. Automated System Bootstrapper (Recommended for Debian/Ubuntu)

Vigilante includes a self-contained Debian/Ubuntu host provisioning script located at the repository root ([`bootstrap.sh`](https://github.com/DeployCoop/vigilante/blob/main/bootstrap.sh)). It automatically installs and configures:

- **Node.js 22.x LTS & pnpm**
- **Docker Engine & Containerd**
- **k3d** (v5.7+) and **K3s** (v1.31+)
- **kubectl**, **Helm 3**, and **mkcert** (with local CA root installation)
- **Kernel sysctls**: `vm.max_map_count=262144` (required for OpenSearch/Elasticsearch) and inotify watchers
- **Ollama AI Runtime** (optional local LLM provider for the AI Analyst)

```bash
# Clone the repository
git clone https://github.com/DeployCoop/vigilante.git
cd vigilante

# Make bootstrapper executable and run with sudo
chmod +x bootstrap.sh
sudo ./bootstrap.sh
```

## 2. Manual Prerequisites & Environment Verification

If you prefer to install dependencies manually on macOS or other Linux distributions, verify the following packages:

| Tool | Minimum Version | Purpose | Installation Guide |
| :--- | :--- | :--- | :--- |
| **Node.js** | `>= 22.5.0` | Runtime Engine | [nodejs.org](https://nodejs.org/) or via `fnm` / `nvm` |
| **pnpm** | `>= 9.0.0` | Monorepo Package Manager | `corepack enable pnpm` or `npm install -g pnpm` |
| **Docker** | `>= 24.0.0` | Containerization Runtime | [docs.docker.com/engine](https://docs.docker.com/engine/install/) |
| **k3d** | `>= 5.5.0` | Lightweight K3s in Docker | `curl -s https://raw.githubusercontent.com/k3d-io/k3d/main/install.sh \| bash` |
| **kubectl** | `>= 1.28.0` | Kubernetes CLI | `curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"` |
| **Helm** | `>= 3.12.0` | Kubernetes Package Manager | `curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 \| bash` |
| **mkcert** | `>= 1.4.0` | Local Trusted TLS Certificates | `apt install libnss3-tools && curl -JLO "https://dl.filippo.io/mkcert/latest?for=linux/amd64"` |

Install repository workspace packages:
```bash
pnpm install
pnpm link --global
```

Verify your environment status at any time:
```bash
vigilante status
```

## 3. Cluster Providers: k3d vs. Host K3s

Vigilante supports two Kubernetes cluster providers:

### A. k3d (Default — Lightweight Docker Container)
Ideal for standard workstations and macOS laptops where Docker Desktop is running:
```bash
# Provision default k3d cluster with kctf and vigil-soc
vigilante up -m kctf,vigil-soc
```

### B. K3s (Native Host Systemd Service)
Ideal for dedicated Linux hosts, lab servers, or bare-metal hypervisors where native kernel access is preferred:
```bash
# Provision directly into local K3s
vigilante up --k3s -m kctf,vigil-soc

# Or via explicit provider flag
vigilante up --provider k3s
```
*Note: When using K3s, ensure your user has read access to `/etc/rancher/k3s/k3s.yaml` (the bootstrapper configures permissions automatically).*

## 4. Local TLS & Domain Resolution (`hostr`)

Vigilante maps all ingress endpoints under `*.vigilante.local` (e.g. `ctf.vigilante.local`, `siem.vigilante.local`, `vigil.vigilante.local`) to local cluster ingress ports (`80` / `443`).

```bash
# Synchronize local domain mappings into /etc/hosts
vigilante hostr

# Check resolution status without modifying
vigilante hostr --check

# Remove managed entries when tearing down
vigilante hostr --remove
```

## 5. Launching Vigilante: Dual Interface Parity

Vigilante provides two frontends sharing the same 32 security engines and cluster state:

### Option 1: Next.js Web Operations Portal (`apps/web`)
Launch the rich browser portal at [http://localhost:3000](http://localhost:3000):
```bash
pnpm dev:web
```
Features 25+ integrated operations views:
- **CTF Player Field Manual & Live Arena** (`/event`, `/ctf`)
- **NastyMap Network Recon & Topology** (`/nastymap`)
- **BattleStation Live SOC (eBPF & IDS)** (`/battlestation`)
- **PCAP Stream Forensics & Live Sniffer** (`/forensics`, `/sniffer`)
- **Kernel Process Lineage Tree** (`/lineage`)
- **Access Control & Audit Log** (`/settings/access`)

### Option 2: React Ink Terminal TUI (`apps/ink`)
Launch the high-performance terminal console:
```bash
pnpm cli
# or directly
vigilante
```
Use `[Tab]` to open the **Operations NavHub** and `[:]` or `[/]` to open the global **Command Palette**.

## 6. Initializing Security & Access Control (CASL RBAC)

Vigilante enforces a fail-closed authorization engine backed by **CASL**. When first installed, it operates in bootstrap loopback mode. Lock down all API routes and provision your initial Owner credentials:

```bash
# Initialize via CLI (generates owner token)
vigilante authz init --name "Admin Owner"

# Or configure a password (>= 12 characters)
vigilante authz init --name "Admin Owner" --password "super-secret-password-123"
```
Or open [http://localhost:3000/settings/access](http://localhost:3000/settings/access) in the Web Portal to initialize and manage principals, roles, scoped grants, and live audit logs.

## 7. Starting the CTF Cyber Range

Ready to compete?

1. Open the **CTF Player Field Manual** at [http://localhost:3000/event](http://localhost:3000/event) or launch via CLI (`vigilante ctf`).
2. Click **Initialize Workspace** to generate `./ctf-workspace/` containing categorized challenge templates (`web/`, `pwn/`, `crypto/`, `rev/`, `forensics/`) with starter Python exploit scripts.
3. Open the **CTF Arena** at [http://localhost:3000/ctf](http://localhost:3000/ctf) to spawn ephemeral `nsjail` challenge pods.
4. Use the **Solver Workbench** (`/event`) and **Socratic AI Mentor** (`/ctf`) to analyze, exploit, and submit flags!
